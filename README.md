# Архитектура BionicPRO

Проект демонстрирует архитектуру системы для обработки данных с использованием микросервисов, CDC (Change Data Capture),
ETL-процессов и аналитической базы данных.

## Структура проекта

- **bionicpro-auth** — сервис аутентификации (Python/Flask)
- **frontend** — веб-интерфейс (TypeScript/React)
- **keycloak** — сервер идентификации и управления доступом
- **crm_db** — база данных CRM (PostgreSQL)
- **olap_db** — аналитическая база данных (ClickHouse)
- **kafka** + **debezium-connect** — потоковая передача изменений данных
- **airflow** — оркестрация ETL-процессов
- **minio** + **cdn-nginx** — объектное хранилище и CDN
- **openldap** — каталог пользователей для Keycloak

## Артефакты и документация

- **Скриншоты** расположены в папке `screenshots/`
- **Схемы C4 модели** расположены в папке `schema/` (включая drawio-файлы и Markdown-описания)

## Быстрый старт

### Запуск инфраструктуры

Вся инфраструктура, кроме сервисов `bionicpro-auth` и `frontend`, запускается через `docker-compose`:

```bash
docker-compose up -d
```

После запуска будут доступны:

- Keycloak: http://localhost:8080 (admin/admin)
- Airflow: http://localhost:8081 (admin/admin)
- Debezium Connect: http://localhost:8083
- MinIO: http://localhost:9001 (minio_user/minio_password)
- CDN-nginx: http://localhost:8888
- CRM DB: localhost:5444
- OLAP DB (ClickHouse): localhost:8123

### Запуск сервисов вручную

Сервисы **bionicpro-auth** и **frontend** необходимо запускать вручную, чтобы избежать проблем с доменами и корректной
работой авторизации.

#### bionicpro-auth

```bash
cd bionicpro-auth
python -m venv .venv
source .venv/bin/activate   # для Windows: .venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

Сервис будет доступен по умолчанию на `http://localhost:5000`.

#### frontend

```bash
cd frontend
npm install
npm start
```

Frontend будет доступен на `http://localhost:3000`.

## Для интервьюера

### Особенности проверки заданий

В рамках проекта выполнялось несколько заданий, которые требовали модификации **одних и тех же файлов**. Поэтому для
корректной оценки выполнения каждого задания необходимо ориентироваться на **историю коммитов** в Git.

Рекомендуется:

1. Просматривать коммиты в хронологическом порядке.
2. Обращать внимание на сообщения коммитов — они отражают суть изменений.
3. Проверять, что каждое задание выполнено в отдельном коммите (или серии коммитов).

### Проверка работоспособности

После запуска всей инфраструктуры и ручного запуска `bionicpro-auth` и `frontend` система должна работать в полном
объёме:

- Авторизация через Keycloak
- Загрузка и отображение данных из CRM
- ETL-процесс, переносящий данные из CRM в ClickHouse
- Кэширование статических ресурсов через CDN

### Возможные проблемы

1. **Доменные имена** — если фронтенд или auth-сервис запущены внутри Docker, могут возникнуть проблемы с CORS и
   обращением к Keycloak. Поэтому рекомендуется запускать их на хосте.
2. **Порты** — убедитесь, что порты 5000 и 3000 свободны.
3. **Инициализация баз данных** — при первом запуске нужно дождаться полной инициализации всех БД (логи в контейнерах).
